## What your code supplies

| Service                      | Provides                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------- |
| `ClaimsForPassword`          | Session claims for an account, or a rejection.                                    |
| Password and session storage | [Managed tables, your own schema, or custom services](/auth/reference/adapters/). |
| `PasswordHashing`            | Argon2id from `@yielded/auth-crypto/Password`, or your own.                       |

You don't need to memorize this list. `AppAuth.layer` names every missing service
in its type, and each method you install adds its own.
[Getting started](/auth/guide/getting-started/) wires these Layers.

## Other methods, same path

Every method follows the same route through your code. Multi-step methods
return a public flow ID between calls; the private binding that ties the steps
to one browser travels as a cookie, like the session.

| Method                                         | Calls                                                                         |
| ---------------------------------------------- | ----------------------------------------------------------------------------- |
| [Password](/auth/guide/passwords/)             | `signIn` → session or additional factor.                                      |
| [Email code or magic link](/auth/guide/codes/) | `beginSignIn` → `signIn` sends the proof → `verifySignIn` → `completeSignIn`. |
| [SMS code](/auth/guide/phone/)                 | `signIn` sends the code → `completeSignIn`.                                   |
| [Passkey](/auth/guide/passkeys/)               | `signIn` → browser ceremony → `completeSignIn`.                               |
| [OAuth](/auth/guide/oauth/)                    | `signIn` → provider redirect → `completeSignIn`.                              |
| [TOTP](/auth/guide/totp/)                      | First factor returns a pending proof → `verifyPending`.                       |

## When a response is lost

Commands that change an account, such as registration or a password reset, take
a request ID. A retry with the same ID returns the stored receipt instead of
running the command again. If a commit's outcome is unknown, look the receipt up
through your storage adapter rather than issuing credentials again.
